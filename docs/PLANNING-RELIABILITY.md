# 排程可靠性与组织者工作区

## 旅游规则排程

`tourism-scheduler.ts` 同时处理规则兜底与模型推荐候选，模型不能绕过程序约束。每次停留包含游览/用餐与排队，站点之间另计交通、休息。餐饮使用午餐/晚餐窗口；普通景区在营业未知时采用9:00–17:00的保守假设，明确列为待确认。名称与近距离位置共同用于去重，避免场馆别名重复。

逐小时预报按完整停留窗口读取。户外候选对降水、空气质量和热风险计入排序；达到当前产品的保守筛选阈值时不予安排。这些阈值是产品筛选规则，不是医学判断、气象预警或安全认证。数据不完整会标记待复核，不能生成已验证天气结论。

先使用坐标估算选择候选，再对拟定的相邻站点请求高德驾车规划。成功取得的驾车预计时间加入15分钟缓冲，失败或新衔接使用带绕行与缓冲的坐标估算。第二轮排程重新检查完整窗口；并不保证全局最短路径，不包括首站前与末站后的酒店通勤，不等于实时导航或已预约车辆。

高德 `opentime_today` 仅适用于查询当日，不将当日营业时间外推为未来日期开放承诺。不规则营业文字、未来日期、节假日和团体接待均保留待确认。来源接口说明：[POI服务](https://developer.amap.com/api/webservice/guide/api/newpoisearch)、[路径规划](https://lbs.amap.com/api/webservice/guide/api/direction)。

删除地点前保存方案快照；删点后重新计算保留地点的时间、天气、估算交通与休息，并更新地图、时间图、规划书。该次修改不重新查询路况，关联地点费用移除、公共费用保留。旧版路线需重新分析才能使用完整排程编辑。

## 证据展示

首要指标改为推荐地点资料关联覆盖率。关联资料不等于营业、预约和接待已验证。官方说明、数据接口和未核验全文的检索摘要分别展示，未取得资料的地点明确列出。搜索入口过滤旅行社排名、跟团推广等内容；旅游路线只保留能关联实际站点的检索摘要，不用通用SEO文章充数。

## 用户信息与场景深化

环境评分风险类别与具体身份分开保存：大学生仍按成年人风险类别计算，但 `audienceDescription` 保存大学生身份，用于地点偏好、确认卡和规划书。人均预算、器材数量与每组人数单独记录；“每组5人”不会覆盖总人数。

- 研学：行前问题、场馆主题任务、证据记录、小组分享和教师评价。
- 运动会：项目排程、同日场地/负责人/参赛编号冲突、结果与异常记录。
- 体育课：按人数、每组规模和器材数计算练习站及轮次，缺器材资料时不假定充足。
- 社区：报名/到场与容量核对任务、需求分区、志愿者分工、参与反馈记录。
- 户外训练：训练目标、基础确认、补给/撤离和天气变化处理。距离、爬升、通行未知时不编造路线参数。
- 旅游：完整时间排程、地点编辑、交通来源与预算明细。

## 六个工作区与数据

分析台、环境地图、执行方案、执行管理、资料库、活动档案分别承担输入、空间分析、文档、项目费用、人工核对及版本复盘。

工作区数据使用原有账户隔离的 `/api/v1/conversation-memory` 保存；访客按会话保留，注册用户按账户保留。项目和费用按城市、活动与日期范围隔离。当前提供组织者账户内的分工记录，不提供跨账户实时协同、通知发送、在线支付或自动场馆预约。参与者说明可下载，默认不含名单。

每次完成分析自动保留版本，最多4份，可载入、比较条件、填写复盘并归档。资料最多60条，项目及费用各100条；服务端记忆总量上限仍为100万字符。资料的“已人工核对”由组织者选择，当前不自动等价为Agent已读取全文。执行记录和费用不是场馆容量或预算可行性的认证。
