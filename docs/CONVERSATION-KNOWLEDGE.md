# 对话问答与知识库维护

对话入口为 `/conversation-planner`。单次问答和规划条件收集分开，避免天气查询被误当作活动规划。

## 三条处理路径

- 天气：城市/区县识别 → 行政区域解析 → Java 逐小时真实预报 → 按全天及上午、下午、晚上汇总。不要求人数、活动类型；查询失败、地点歧义和超出七天范围均明确提示，不生成虚构预报。
- 知识问答：先检索本地条目；实时信息或未命中问题使用已有百度/Tavily 搜索。模型仅基于检索摘要回答，返回原文链接、来源类型与获取时间。模型不可用时展示带出处的搜索摘要；没有资料则说明无法可靠回答。
- 规划：继续采用多轮条件确认；条件齐全后执行真实环境查询和方案生成。问答返回 `command: answer`，不会修改或运行现有规划。

## 本地知识库

文件：`frontend/src/lib/conversation-knowledge.ts`。

当前覆盖天气预报、空气指标、预约、餐饮预算、活动组织、同行与无障碍、交通、住宿、装备、雨天备选、研学校园、社区训练、来源说明、产品使用、能力边界，共 15 类。

这是可维护的小型知识库，不是完整百科或向量数据库。每个条目包含稳定 ID、标题、匹配规则、正文及可选官方参考链接。增加条目时检查匹配冲突；不要将实时天气、票价、营业时间、热榜或未经核实的内容写入静态条目。平台内部说明标记为行知知识库，不能冒称外部权威资料。

## 配置及限制

复用现有 `WEB_SEARCH_PROVIDER`、`BAIDU_SEARCH_API_KEY` / `TAVILY_API_KEY`、账户模型配置与服务端模型配置。地理解析使用 `AMAP_WEB_SERVICE_KEY`，天气查询使用 `BACKEND_INTERNAL_URL` 对应的 Java 服务。所有密钥留在服务端。

搜索摘要不是全文验证，也不能保证正确。无结果、权限失败、限流、超时、模型不可用须区分有无可用证据，不能将工具失败写成成功。个人诊断和法律、财务结论不由通用知识回答替代。后续可在该检索入口增加经审核的文档索引，不需要重写对话 UI。

## 验证

运行 `node --experimental-strip-types --test tests/*.test.mjs`（在 frontend 目录）。新增回归覆盖天气与规划分流、知识问题不污染规划、中文问题、任意城市提取、真实数值汇总、空数据拒答及通用联网搜索出处校验。

界面显示消息作者、回答类型、原文来源和能力提示，保留思考计时与水墨进入效果。输入法组合输入期间按 Enter 不发送。
