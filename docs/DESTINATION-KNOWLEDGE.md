# 城市与人群知识能力

## 查询范围

城市介绍不再依赖固定城市白名单。短城市名和“介绍一下某地”会先通过高德行政区划确认，使用行政区代码限定后续地点检索。支持的数据范围取决于高德与搜索服务覆盖，不能承诺每个行政区都有完整历史、饮食或场馆资料。位置不唯一、接口失败或资料不足均说明原因。

介绍由城市概况、文化、当地地点和饮食资料构成。搜索摘要按相关段落整理，并显示出处；不声称读过全文。已有审核资料如西安简介仍可复用，其他城市通过通用流程补充，不把无关新闻当作城市介绍。缺少某一主题时保留“资料不足”，不编造。

## 人群筛选与多轮问答

`destination-knowledge.ts` 保存七类可维护的人群规则：亲子、学生、老人、无障碍需求、成年同行、情侣、独自出游。规则仅用于地点类别初筛，不是医学、无障碍或安全认证。

推荐实际执行：确认城市 → 查询本地博物馆、公园等候选 → 按人群偏好、室内要求及减少步行条件筛选 → 给出具名地点、理由、来源和待核实事项。不会给不匹配的地点凑数。实时检索无结果时可使用现有内置地点候选，但标明尚未实时核验。

`knowledgeContext` 独立于正式规划条件，保留当前城市、人群、孩子年龄、室内偏好、步行要求、预算倾向和上一轮候选。支持“孩子五岁”“雨天呢”“换成老人”“少走路”“换一批”“美食呢”等追问；不同城市切换后重新限定行政区。界面显示已理解偏好并可清除。进入正式规划时重置知识问答上下文。

没有确定目的地时可先比较少量内置城市方向，并提示未评估交通、开放和费用；选定城市后再查询当地数据。“不同人群分别推荐”可在同一城市展示不同筛选方向。

## 可维护的扩充方式

1. 新增稳定事实时，在 `city-introduction.ts` 的资料中记录可核对来源，不填实时票价、排名或开放时刻。
2. 新增人群规则时，说明偏好、排除项、推荐理由与需要确认的事项，更新匹配及筛选测试。
3. 搜索和高德缓存有容量及有效期限制；缓存只是降低请求开销，不意味着资料已审核成为永久知识。
4. 用户发言不是事实来源。不会自动把聊天内容、模型回答或搜索摘要永久写入审核知识库。持续深化依赖有出处的资料补充、规则维护和回归验证。

## 验证案例

- “绍兴”“安顺”“介绍一下张家界”：验证非白名单城市。
- “杭州哪些地方适合大学生”“在绍兴带老人去哪里”：城市与人群同时识别。
- “亲子适合去哪儿”→“杭州”→“孩子五岁”→“下雨呢”→“换成老人、少走路”：条件沿用与更正。
- “轮椅同行”：不承诺任何未经确认的无障碍设施。
- “预算不多”：不把公园或博物馆自动判定为免费。
- “数据来源”“明天气温”：继续走来源或天气回答，不受城市推荐上下文污染。

环境变量沿用现有 `AMAP_WEB_SERVICE_KEY`、百度/Tavily 搜索配置，不新增依赖或公开密钥。
