# 部署说明：阿里云 ECS + 域名 lht574.cn

本文档描述如何把「适候 · AI 户外活动环境决策平台」发布到阿里云服务器（公网 IP `8.137.86.65`），并绑定域名 `lht574.cn`，使用户通过浏览器即可正常访问。

| 项目 | 值 |
| --- | --- |
| 服务器 | 阿里云 ECS，公网 IP `8.137.86.65`，root 登录 |
| 域名 | `lht574.cn`（含 `www.lht574.cn`） |
| DNS 服务器 | `dns25.hichina.com`、`dns26.hichina.com`（阿里云万网 DNS） |
| 技术栈 | Docker Compose：MySQL 8.4 + Spring Boot 后端 + Next.js 前端 + Nginx 入口 |
| 对外端口 | 80（HTTP，可选升级 443/HTTPS） |

---

## 〇、前置检查

1. ECS 安全组已放行 **80 端口**（TCP）。控制台路径：ECS 实例 → 安全组 → 配置规则 → 入方向添加 `80/tcp，源 0.0.0.0/0`。
2. 域名 `lht574.cn` 已完成 **ICP 备案**并绑定到该 ECS（阿里云大陆服务器要求备案，未备案会被拦截 80/443 端口）。
3. 本地能通过 SSH 登录：`ssh root@8.137.86.65`。

## 一、安装 Docker（服务器执行一次）

```bash
ssh root@8.137.86.65

# 安装 Docker 与 Compose 插件（以 Alibaba Cloud Linux / CentOS 为例）
dnf config-manager --add-repo https://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo
dnf install -y docker-ce docker-compose-plugin
systemctl enable --now docker

# Ubuntu 则使用：
# apt-get update && apt-get install -y docker.io docker-compose-plugin

docker version && docker compose version   # 验证安装成功
```

## 二、上传代码

任选其一：

```bash
# 方式 A：服务器直接克隆 GitHub 仓库
dnf install -y git && cd /opt
git clone https://github.com/liangjie798/The-Unfallen.git amap-jsapi   # 仓库名以实际为准
cd amap-jsapi

# 方式 B：本机打包上传
# scp -r "G:/Ai Web/amap-jsapi" root@8.137.86.65:/opt/amap-jsapi
```

## 三、配置环境变量

```bash
cd /opt/amap-jsapi
cp .env.example .env
vi .env
```

必填项：

```ini
MYSQL_ROOT_PASSWORD=一个足够长的随机密码
MYSQL_PASSWORD=另一个足够长的随机密码
```

可选项（不填也能运行）：

```ini
# 高德地图密钥：不填时地图区域降级为坐标视图，仍可正常决策
NEXT_PUBLIC_AMAP_KEY=
NEXT_PUBLIC_AMAP_SECURITY_CODE=

# 服务端大模型（可选）：填写后优先于默认免费开源模型
SILICONFLOW_API_KEY=
SILICONFLOW_MODEL=Qwen/Qwen2.5-7B-Instruct
DEEPSEEK_API_KEY=
```

> 说明：系统默认接入免费开源大模型（Pollinations 托管的 Mistral，无需密钥）。即使上面全部留空，AI 旅游路线等功能依然可用；用户也可以在网页「AI 模型配置」页填自己的模型地址与密钥，立即生效且互不影响。

## 四、构建并启动

```bash
docker compose up -d --build     # 首次构建约 5-15 分钟
docker compose ps                # 四个服务应为 running/healthy
curl -I http://127.0.0.1         # 期望 HTTP/1.1 200
curl http://127.0.0.1/api/v1/cities/hangzhou   # 后端连通性验证
```

内存不足 2G 的实例如构建失败（前端 build 被杀），先加 2G swap：

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
docker compose up -d --build
```

## 五、绑定域名 lht574.cn（阿里云 DNS 控制台操作）

该域名的 DNS 服务器为 `dns25.hichina.com` / `dns26.hichina.com`（阿里云默认解析），直接在 **阿里云控制台 → 云解析 DNS → lht574.cn → 解析设置** 中添加两条记录：

| 记录类型 | 主机记录 | 记录值 | TTL |
| --- | --- | --- | --- |
| A | `@` | `8.137.86.65` | 10 分钟 |
| A | `www` | `8.137.86.65` | 10 分钟 |

Nginx 入口（`deploy/nginx.conf`）已配置 `server_name lht574.cn www.lht574.cn _;`，无需再改。

验证解析生效：

```bash
nslookup lht574.cn      # 期望返回 8.137.86.65（本地验证）
dig @dns25.hichina.com lht574.cn +short   # 指定权威 DNS 验证
```

## 六、浏览器验收

DNS 生效后（通常 5-30 分钟），浏览器访问：

- `http://lht574.cn` → 首次访问进入引导页（顶栏可回到工作台）
- `http://www.lht574.cn` → 决策工作台
- 验收要点：城市搜索下拉能搜到区县、地图出现深浅色块与图例、生成决策/生成旅游路线正常、`/hourly` 与 `/settings` 页可访问

## 七、（推荐）启用 HTTPS

```bash
# 方式一：certbot 自动签发（需域名已备案且解析生效）
dnf install -y certbot && certbot certonly --standalone -d lht574.cn -d www.lht574.cn
```

然后在 `deploy/nginx.conf` 增加 443 server 块（证书路径 `/etc/letsencrypt/live/lht574.cn/`），把 80 端口重定向到 HTTPS，并在 `docker-compose.yml` 的 nginx 服务追加 `- 443:443` 与证书目录挂载，`docker compose up -d` 重启即可。

## 八、日常运维

```bash
docker compose logs -f frontend    # 看前端/大模型日志
docker compose logs -f backend     # 看后端日志
docker compose restart             # 重启
docker compose up -d --build       # 更新代码后重建
docker compose down                # 停止（数据卷保留）
```

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 域名访问被拦截/备案提示 | 完成 ICP 备案并将备案主体绑定到本 ECS |
| 解析不生效 | 确认 A 记录已添加；`whois lht574.cn` 检查 DNS 是否为 dns25/26.hichina.com |
| 502 Bad Gateway | `docker compose ps` 检查 frontend/backend 是否存活，看日志定位 |
| 天气数据报"数据源暂不可用" | 服务器出网访问 Open-Meteo 受限时检查防火墙/出方向规则 |
| AI 路线一直用内置兜底 | 默认免费模型偶发超时会自动降级为精选路线；可在 /settings 页配置自己的模型地址与密钥提升成功率 |
